# Стенд для проверки глазами

Приложение маленькое, сборки и тестов в нём нет. Но вёрстку и поведение
нужно **видеть**, а не угадывать: почти всё, что чинилось в прошлый раз —
мигание экрана раз в минуту, наезжающая подпись «сейчас», слишком крупные
разрывы в ленте — на глаз с телефона не заметно, а на снимке видно сразу.

Никаких зависимостей ставить не надо. Статику отдаёт `node:http`, браузером
управляем по CDP через голый `WebSocket` — он встроен в Node с 22-й версии.
Chrome берётся из стандартного места, либо из переменной `CHROME_PATH`.

```bash
node tools/shoot.mjs обычный          # как выглядит день
node tools/shoot.mjs тёмная           # тёмная тема
node tools/shoot.mjs закрытый         # все дела закрыты
node tools/shoot.mjs просрочено       # есть дела с прошлых дней
node tools/shoot.mjs пустой           # ничего не запланировано
node tools/shoot.mjs месяц            # календарь с плотностью по дням
node tools/shoot.mjs повтор           # день с повторяющимся делом
node tools/shoot.mjs год              # весь год полосами
node tools/shoot.mjs голос            # день с голосовыми заметками
node tools/shoot.mjs подписки         # список подписок с итогами
node tools/shoot.mjs обычный 1200     # высота окна, если нужен весь экран целиком

node tools/check.mjs                  # клики, вкладки, листы, консоль
node tools/deploy.mjs                 # как поведёт себя на GitHub Pages

node tools/vapid.mjs                  # ключи VAPID для пуша, один раз
node tools/pushsend.mjs '<адрес>'     # тестовый пуш на телефон
```

`push.html` из командной строки не запускается: он открывается **на телефоне**
по выложенному адресу `https://yuriyrs.github.io/napominalka/tools/push.html`.

Снимки кладутся в `tools/out/` — эта папка в `.gitignore`.

## Что чем проверяется

`shoot.mjs` — только внешний вид. Демо-задачи кладутся в IndexedDB до загрузки
приложения, поэтому снимок получается осмысленным, а не пустым экраном.

`check.mjs` — поведение: отметка дела, переезд строки в «Сделано», закрытие
дня, переключение вкладок, листы и цвет статус-бара при трёх сочетаниях
выбранной темы и системной. Отдельно проверяются действия над делом — стенд
**по-настоящему держит кнопку мыши 650 мс**, а не зовёт обработчик напрямую,
поэтому долгое нажатие проверяется вместе с отменой по сдвигу пальца.
Там же измеряются зоны нажатия: план требует не меньше 48 px.

Ошибки и предупреждения консоли собираются за весь прогон; в конце печатается
`консоль чистая` либо список проблем.

**Голосовые заметки проверяются по-настоящему.** Chrome поднимается
с `--use-fake-device-for-media-stream`: микрофон поддельный, но запись
настоящая — MediaRecorder, куски, сборка в blob, попадание звука в базу.
Подделка на месте записи не проверила бы ничего.

Два правила, без которых эти проверки не работают:

- **Играть заставляет только настоящее нажатие.** Программный `click()` Chrome
  не считает жестом пользователя и звук не пускает — для этого в стенде есть
  `click()`, который жмёт мышью по-настоящему.
- **Окна `alert` стенд закрывает сам.** В headless-браузере такое окно
  останавливает страницу насмерть: CDP не получает ответа никогда, и прогон
  висит без единой строки в выводе. Сказанное при этом запоминается и печатается
  в конце — приложение показывает `alert` после загрузки копии, и знать об этом
  стоит.

Самые ценные проверки голоса идут **с перезагрузкой страницы**: копия
загружается обратно (дела и голоса обязаны вернуться), и метла убирает
запись-сироту, не тронув настоящие. Без перезагрузки метла не ходит вовсе.

`deploy.mjs` — выкладка. На GitHub Pages приложение лежит не в корне, а по пути
`/имя-репозитория/`, и это классическое место, где молча ломается всё сразу:
иконки, манифест, область видимости сервис-воркера, офлайн-кэш. Стенд поднимает
статику под таким же префиксом (переменная `BASE`), проверяет каждый ресурс
из манифеста и **выключает сеть**, после чего открывает приложение заново.
Если кэш собран с относительными путями — приложение поднимется, если нет —
будет пустой экран.

`vapid.mjs`, `push.html` и `pushsend.mjs` — проверка доставки пуша. Это не про
приложение, а про то, доедет ли напоминание до телефона вообще, и проверяется
это без сервера: пара ключей и один POST-запрос. Зависимостей тут тоже нет —
подпись VAPID собирается на голом `node:crypto`.

`push.html` открывается на телефоне по выложенному адресу, а не локально:
подписка привязана к origin и к регистрации сервис-воркера. Регистрирует
страница **тот же** `sw.js` и с той же областью видимости, что приложение,
поэтому подписка получается ровно та, которой приложение и будет
пользоваться. Своя, отдельная регистрация доказала бы не то.

`pushsend.mjs` шлёт пуш **без полезной нагрузки**, и это намеренно: у пуша без
текста нет шифрования (RFC 8291), только подпись VAPID, — значит, ломаться
нечему и проверяется главное, доходит ли вообще. Текст добавится, когда будет
что проверять. Закрытый ключ `vapid.mjs` кладёт **вне репозитория**, в домашний
каталог: репозиторий публичный, и ключ в нём — открытая дверь для любого, кто
знает адрес подписки.

Проверять надо **в покое, а не на открытой странице**. На открытой пуш приходит
за секунды и не доказывает ничего; в покое — за полторы-три минуты, и вот это
уже честная цифра. Отсюда и задержка при отправке: телефону надо дать полежать.

## Зачем свой профиль на каждый запуск

`open()` в `cdp.mjs` создаёт новый профиль браузера при каждом запуске.
Если этого не делать, service worker и IndexedDB переживут прогон, и следующий
снимок покажет **прошлую** версию приложения — ровно та ловушка, из-за которой
раньше правки не доходили до установленного PWA.

## Путь к каталогу брать только через `fileURLToPath`

Проект лежит по пути с кириллицей, и на этом уже спотыкались.

`new URL('.', import.meta.url).pathname` на Windows отдаёт путь **в процентах**:
вместо `Прил` — `%D0%9F%D1%80%D0%B8%D0%BB`. Скрипт, который считает `out` так,
создаст несуществующее дерево и передаст его Chrome как `--user-data-dir`.
Chrome поднимется, страница откроется — и откажет только Cache Storage:

```
UnknownError: Failed to execute 'open' on 'CacheStorage': Unexpected internal error.
```

Сервис-воркер после этого не установится, регистрация исчезнет, **и в консоли
не будет ни одной строки**. Выглядит это как «сервис-воркер сломан» или «сайт
не работает», хотя сломан скрипт: с явным путём тот же прогон проходит.

Штатные `shoot.mjs`, `check.mjs` и `deploy.mjs` считают путь правильно:

```js
const HERE = path.dirname(fileURLToPath(import.meta.url));
```

Разовые скрипты рядом со стендом должны делать так же. Проверять себя просто:
если после первого же обращения к `caches.open()` браузер отвечает внутренней
ошибкой — первым делом посмотреть на путь к профилю.

## Как добавить состояние

Наборы дел лежат в `cdp.mjs`: `DEMO_DAY` (день), `DEMO_LATE` (два дела
с прошлых дней), `DEMO_MONTH` (разброс по месяцу — нужен, чтобы в календаре
были видны все уровни плотности), `DEMO_REPEAT` (серия повторов), `DEMO_YEAR`
(разброс по всем месяцам плюс серии вперёд), `DEMO_VOICE` (день с голосовыми
заметками), `DEMO_SUBS` (подписки — суммы в копейках, как и в базе, а вместо
даты `inDays`, потому что демо считается от сегодняшнего дня).

Новое состояние — строка в объекте `CASES` в `shoot.mjs`: список задач, тема,
высота окна, `subs` и, если нужно, `tab` — на какой вкладке открыть (`month`,
`year`, `subs` или `today`).

**Версия базы в `seedExpr` обязана совпадать с `db.js`.** Это записано
и в §7 плана, и здесь, потому что ошибка тихая и наступают на неё каждый раз:
стенд открывает базу жёстко, и, разойдись они, он получит `VersionError`
на любом профиле, где приложение успело создать базу новее. Сейчас версия 3.

Звук для `DEMO_VOICE` собирается прямо в `seedExpr` — короткий WAV из сорока
четырёх байт заголовка и синусоиды. Настоящий blob нужен потому, что кнопку
проигрывания надо чем-то проверить, а пустышка на месте звука проверкой
не будет. Длительность в описании обязана совпадать со звуком: иначе
проигрыватель покажет одно, а сыграет другое.

Проверки календаря в `check.mjs` стоят двумя частями, и это намеренно.
Взаимодействие — тап по дню, возврат, листание месяца — проверяется на общем
потоке. А плотность — в конце, где данные пересеиваются на `DEMO_MONTH`:
на `DEMO_DAY` дела есть только у сегодняшнего дня, и все точки вышли бы либо
пустыми, либо максимальными, то есть проверка ничего бы не доказывала.

Повторы проверяются там же, в конце, и тоже по этой причине: серия
размножается на год вперёд, и все счётчики выше поехали бы. Главная проверка
там — с перезагрузкой: удалили одно вхождение, перезагрузили, убедились, что
не вернулось. Так же и с отменённой серией. Без перезагрузки это не проверить:
возвращает удалённое именно `syncSeries`, и только при следующем запуске.

Якорь серии в наборе обязан совпадать со временем её первого вхождения —
поэтому в `cdp.mjs` есть свой `dayAt()`, считающий время так же, как `D()`
внутри `seedExpr`.
